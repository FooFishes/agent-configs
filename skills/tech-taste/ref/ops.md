# ops

一句话立场：单机全 Docker 加反向代理加 Jenkins 自动构建，一份 .env 开箱即用；改线上配置先备份；发版自动填好信息最后人工确认；监控先抓 crash-free。

## 条目
### 部署目标是一份 .env 开箱即用，容器之间的连接由 Compose 自动注入

为什么："我希望我能够传入一个 .env 然后构建完就是out-of-box 的"；"数据库(包含主库和MySQL实训)和Redis在容器内可以不用配置吧?"。用户只填密码、密钥、管理员和外部入口，其余自动。

例外：暂无。

来源：2026-09-28 training-sys（Codex）。

### 部署形态：单机全 Docker，容器同一网络，反向代理对外，Jenkins 自动构建，Cloudflare 管 DNS

为什么："所有部署都使用了 Docker 容器, 使用反向代理代理出去. Docker 容器之间加入同一网络进行通信. 域名需要在 Cloudflare 下新增 dns 解析记录. 然后需要为该项目配置 Jenkins 自动构建, 你可以参考之前的项目的自动构建方式."。"参考之前的项目"说明这是跨项目惯例。TLS 终止在上级网关，应用层不管证书："把其中 Caddy 去掉, 我们不需要自动申请 https 证书"。

### 追求全自动构建；发版这一步自动填好信息，最后保留人工确认

为什么："现在我们是半自动化的，有没有全自动化构建的方案？"，"改，交给 CI"。"上传这一步我们不能随便做，因为它实际上是一个发版的过程... 我们可以选择某一次构建去上传，然后根据那次的 changelog 帮我们填好信息，再人工确认一下... 我们可以把信息放在一个 changelog 文件中"。Nightly 构建"在有多个请求过来时，只保留最新的一个，之前没有完成的直接丢弃"。
