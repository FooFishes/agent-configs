# tooling

一句话立场：工具链按官方推荐方式搭，CI 和 Dockerfile 是初始化标配。配置收敛到一份文件加环境变量，运行时跟最新 LTS 并钉死版本。部署是单机全 Docker 加反向代理，一份 .env 开箱即用。

## 条目

### 脚手架、构建和 Docker 按官方推荐方式搭，不自创

为什么：两次都明确以"官方推荐"为理由，比如 pnpm 的 standalone 部署方式。官方方式有人维护，自创的只有自己维护。

例外：暂无。

来源：Nova，2026-10。

### 项目初始化就补 CI 和 Dockerfile，CI 必须绿；每个仓库一个一键启动脚本

为什么：CI 失败会连续追到修好为止，"又失败了"，"依旧失败"。启动脚本三个项目都要了，本机开发一条命令起前后端。

例外：暂无。

来源：Nova、webhook-relay、training-sys、sentry-panel，2026-09 至 10。

### 配置收敛到一份文件加环境变量占位，旁支配置合并后删除；部署目标是一份 .env 开箱即用

为什么："也迁移一下啊"说明期望相关配置一并整理。部署时只填密码、密钥、管理员和外部入口，容器之间的连接由 Compose 自动注入。

例外：暂无。

来源：training-sys，2026-09。

### 运行时和依赖跟最新 LTS 或 stable，用版本管理器钉死，定期检查可升级项，升级时顺手迁移新语言特性

为什么：装正确的版本，不把路径指向另一个版本凑合："我装个新的 jdk17 不行吗 为什么要指向 21"。多平台 fork 的语言版本必须一致，这是共用一份代码的前提。生成文件只重新生成，不手改。

例外：升级时不顺手换 UI 库。

来源：training-sys、isdu-app、eat_what_app，2026-09 至 10。

### 部署形态：单机全 Docker，容器同一网络，反向代理对外，TLS 终止在上级网关，应用层不管证书，自动构建

为什么："参考之前的项目的自动构建方式"说明这是跨项目惯例。应用层的自动证书组件"不需要"，直接去掉。

例外：暂无。

来源：AnkerHackathon、webrtc-turn，2026-10。

### 引入新的外部服务、模型或基础设施组件必须先经过用户，不需要的组件直接去掉

为什么："唉唉 不要随便用呀, 我只允许了那两个模型"。外部依赖既是成本也是选型决定，不能由 Agent 顺手加。

例外：暂无。

来源：AnkerHackathon、webrtc-turn，2026-10。

### 改线上配置、换依赖前先备份，保证可回滚

为什么：换模型时"backup 一下方便恢复了替换回去"，改网关配置"先备份"。

例外：暂无。

来源：AnkerHackathon，2026-10。

### 追求全自动构建，发版这一步自动填好信息，最后保留人工确认

为什么：上传是发版，"不能随便做"。选某次构建上传，按 changelog 自动填信息，再人工确认。多个构建请求只保留最新的。

例外：暂无。

来源：isdu-app、eat_what_app，2026-09 至 11。
