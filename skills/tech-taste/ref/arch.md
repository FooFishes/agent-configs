# arch

一句话立场：按职责定形态，通用抽象不特判，外部服务加抽象层不绑定供应商；遇到架构问题选正确的隔离边界而不是局部补丁。

## 条目

### 业务差异用通用抽象和数据表达，不在代码里按型号或场景写特判

为什么：先后三次主动盘问"你是不是有针对某些产品做特定的数据建模"，"我们目前有没有针对某些型号进行特判的素材或流程?"，然后拍板："那我们应当为我们的设备进行通用的抽象设计, 而非进行特判. 这种代码数据无法仅仅通过上传文档和产品信息生成, 我们应当从我们的信息库中区查询."差异化的数据从知识库或配置里来，不写进代码。

例外：暂无。

来源：2026-10-14、10-16 AnkerHackathon。

### 会变的展示映射做成配置数据，不硬编码

为什么："在设置页面加上映射规则, 比如 prod -> 生产, 这样防止硬编码导致的无法维护."

例外：暂无。

来源：2026-09-07 sentry-panel 两端。

### 外部服务（搜索、模型供应商）必须有抽象层，不绑定供应商

为什么："搜索 API 需要做出抽象, 具体内容不针对某个语言."；列产品亮点时把"不绑定供应商"当作对外宣讲的点；模型接入先在 gateway 里做通用服务。

例外：暂无。

来源：2026-10-11 至 10-25 Nova、AIC。

为什么：Agent 倾向轻量方案时用户否决："服务端需要是一个重的而不是轻量的 Worker. 我们会承载账号, 鉴权, 统计, 同步等多种功能."

例外：暂无。

来源：2026-10-12 Nova。

### 遇到跨域、鉴权、CSP 这类架构问题，选正确的隔离边界，不放宽安全设置打补丁

为什么：iframe 预览同时碰上 CSP、相对路径和鉴权三重问题，用户选了独立域名托管加一次性票据的方案，愿意为此配 DNS 和通配证书："预览如果独立成 URL 的话, 会不会好一些, 就类似托管了一下网页"，"我们可以加上 dns, 也可以申请域名, 你写一下吧"。

例外：暂无。

来源：2026-10-09 training-sys（Codex）。

来源：2026-10-16 AnkerHackathon。

## 待确认

下面几条只出现在 Agent 整理的项目文档里，对话里还没有直接印证，不要当作已确认的品味。

- 业务规则和决策核心放进无 IO 的纯函数包，不碰网络、数据库和 UI 框架。
- 分层依赖只能往下走，用架构测试或 lint 规则强制。
- 前后端共享的类型和 schema 只定义一次，所有进程边界都过校验。
- 运行中的系统不接 Mock，数据只来自真实来源。
