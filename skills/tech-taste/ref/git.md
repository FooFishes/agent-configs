# git

一句话立场：小步独立提交，一个提交只做一件事。提交信息是英文 type(scope) 加中文标题，不带 AI 署名。单人项目直接在主分支上做。

## 条目

### 小步独立提交，一个提交只做一件事；只提交本次改动，同一文件里不相关的 hunk 挑出去

为什么：这是所有对话里重复最多的一条，四个项目里超过三十次。"每一小步更改都要进行提交啊, 不要写大提交"。多个会话并行改同一工作区时，"同一文件里别处的改动不要带进去"，从不 `git add -A`。默认不接受"顺手带上"。

例外：暂无。

来源：training-sys、AnkerHackathon、Nova、eat_what_app，2026-09 至 11。

### 提交信息用英文 Conventional Commits 前缀加中文标题，scope 用功能模块名，只写标题不写 body

为什么：两次连续纠正定下的格式：用英文标题被说"为什么要使用英文提交信息"，改成全中文又被说"怎么前面那一部分也给我换成中文了"。内容太多先拆提交，拆不开才用 body。提交信息里不提开发阶段编号和文档序号。

例外：拆不开的多项内容可以写进 body。

来源：training-sys、Nova、AnkerHackathon，2026-09 至 10。

### 提交里不带 Co-Authored-By 或任何 AI 署名尾注

为什么：四个项目里说了至少五次，"Co Author 去掉"。如果一定要标注 AI 参与，只接受一行 Generated by 加模型名。

例外：暂无。

来源：AIC、Nova、seekbench、AnkerHackathon，2026-10。

### 单人项目直接在主分支开发，已有分支 fast-forward 或 rebase 回去然后删掉

为什么：至少七次原话，"直接 ff 吧"，"之后所有更改直接在主分支上开发就好"。偶尔走 PR 只是过个流程，不会等 review。

例外：实验性的大改动开 experiment 分支，事后按模块逐项择优并回主分支，不是整条分支二选一。有持续交付的 App 项目按发布节奏用 develop 出 Nightly、tag 出 Release。

来源：sentry-panel、training-sys、Nova、isdu-app，2026-09 至 10。

### 仅本地使用的文件、临时文件、构建产物和 AI 工具目录不进仓库，误提交立刻删掉并补 .gitignore

为什么："这是仅本地使用的啊,,, 为什么要提交"。录屏、评测结果、.tanstack 临时目录、各家 AI 工具的配置目录都被要求清出去。

例外：暂无。

来源：AnkerHackathon、Nova、isdu-app、eat_what_app，2026-10 至 11。

### push 是有意的发布动作，推之前要知道会带上什么、会触发什么

为什么：主分支自动部署的项目里会明确控制推送时机，"Don't push yet"，"先不提交, 我看完成片再说"。

例外：暂无。

来源：AnkerHackathon，2026-10。
