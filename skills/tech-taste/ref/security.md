# security

一句话立场：密钥不入库也不给默认值；认证走外部身份源不自建；安全检查覆盖完整路径；隔离边界宁可多配一个域名也不放宽。

## 条目

### 密钥和端点类配置不给默认值，密钥绝不入库

为什么：Agent 给了默认模型和端点值，被否："不设置默认值. 然后你可以把这个数据作为测试. 确保不会把密钥提交上去"；"API key 我放在 .env 的 TYPESAFE_API_KEY"。webhook-relay、wish-note、webrtc-turn 的配置都走 .env。

例外：暂无。

来源：2026-10-12、10-21 Nova；2026-09 至 10 月多个小项目。

### 认证走外部身份源（OIDC、OAuth、已有系统登录），不自建注册体系

为什么："加一个通过Sentry登录, (加上 Sentry Logo)"；"删除注册功能, 清除注册界面"（保留学校 OIDC）；"对老 CAS 登录进行剥离"；内部工具"倒也不用这么严格的认证, 我们只是需要做到能够登入并查看登入log就好... 直接走Sentry登录了"。

例外：暂无。

来源：2026-09-03 isdu-app；2026-09-04 sentry-panel；2026-09-26 training-sys。

### 安全检查覆盖完整路径，重定向每一跳都要查

为什么：SSRF 修复方案是用户自己写的："fetchHtml 改为 redirect: 'manual', 自己跟随重定向 (最多 5 跳), 每一跳的 Location 解析成绝对地址后都经 assertPublicUrl ... 检查"。

例外：暂无。

来源：2026-10-13 Nova。

### 多租户和未登录场景的数据隔离要主动核查

为什么："在未登录的情况下, 用户之间会存在看到其他用户的对话的情况吗"。会话简报里的规则"已被他人占用要表现得和不存在一样，不泄露订单存在"与此一致。

例外：暂无。

来源：2026-10-15、10-17 AnkerHackathon。

### 不削弱安全边界来消除噪音，宁可多配域名和证书做正确的隔离

为什么：预览方案选了独立域名加一次性票据，见 arch。Agent 明确反对为消 postMessage 噪声加 allow-same-origin 时，用户未反对。

例外：暂无。

来源：2026-09-29、10-09 training-sys（Codex）。

### 发现代码库里曾经泄露过的密钥，要当作教训写进规约

为什么：eat_what_app 的 AGENTS.md 记着"legacy 分支的 pubspec.yaml 曾提交过 Sentry auth token，不要重蹈覆辙"，这条是用户经历过的事。

例外：暂无。

来源：2026-11-05 eat_what_app AGENTS.md（文档辅助）。
