# security

一句话立场：密钥不入库也不给默认值，认证走外部身份源，安全检查覆盖完整路径，隔离边界宁可多配一个域名也不放宽。

## 条目

### 密钥和端点配置不给默认值，密钥绝不入库

为什么：默认值会让错误配置静默工作。经历过 token 被提交进仓库的事故，之后把它写进了项目规约。本地密钥放 .env 或 dotfile 由脚本读取，CI 密钥直接设进 CI。

例外：暂无。

来源：Nova、eat_what_app 及多个小项目，2026-09 至 11。

### 认证走外部身份源，不自建注册体系

为什么：注册体系是一堆要维护的边缘：找回、验证、风控。三个项目都是删掉注册、接 OIDC 或已有系统的登录。内部工具的要求更低，能登入并留下登录日志就够。

例外：暂无。

来源：isdu-app、sentry-panel、training-sys，2026-09。

### 安全检查覆盖完整路径，不信任表面信息，隔离要主动核查

为什么：SSRF 的修复方案是自己写的：手动跟随重定向，每一跳解析成绝对地址后都过检查。上传文件校验魔数而不是信扩展名。多租户和未登录场景会主动问"用户之间会看到对方的对话吗"，不存在和无权限要表现一致。

例外：暂无。

来源：Nova、AnkerHackathon、training-sys，2026-10。
