# 技术品味目录

这是所有品味文章的目录。先读这里，再按需要打开具体的文章。

每篇文章占一行，写上文件名、这篇覆盖什么，以及用户在这个主题上的一句话立场。文件名尽量短，一个词最好，文章讲什么交给描述来说，不要把含义塞进文件名里。

文章按主题分成几组。分组只是为了方便在目录里找，并不对应子目录，所有文件都平铺在 ref 下面。新主题放不进现有的组，就再加一组。

第一批内容是 2026-11-07 从 2026-08 至 2026-11 的历史对话里提炼的，以用户原话为准；项目文档里有、对话里没印证的条目放在文章末尾的"待确认"里，不要当作已确认的品味。

## 设计

架构、接口、数据建模这些系统层面的决策。

- [arch](arch.md)：分层、抽象时机、服务形态、实时通信。立场是按职责定形态，通用抽象不特判，外部服务加抽象层不绑定供应商，架构问题选正确的隔离边界而不是局部补丁。
- [api](api.md)：响应形状、契约、端点写法。立场是响应统一包成 code、message、data，成功码 0，OpenAPI 进仓库当契约，客户端严格照后端最新实现，未定的部分留空不编。
- [data](data.md)：缺失数据、迁移、校验、统计口径。立场是缺失的数据按缺失处理不补造不伪装，schema 变更先问，不信任扩展名这类表面信息。
- [security](security.md)：密钥、认证、隔离边界。立场是密钥不入库也不给默认值，认证走外部身份源不自建，安全检查覆盖完整路径，隔离边界宁可多配域名也不放宽。
- [llm](llm.md)：模型选型、评测、Agent 设计。立场是判断类任务交给模型而不是规则，但选型靠自己跑基准，替换前先做评测集，确定性的事情由代码做，守卫做减法不整条拒绝。
- [design](design.md)：设计稿与实现的关系。立场是 App 是产品本体，设计稿只是方向性的 Guide，原型冻结以 App 为准，Web 原型不能 1:1 搬到移动端。

## 代码

命名、风格、错误处理这些写代码时的取舍。

- [style](style.md)：简练、复用、兼容层、死代码。立场是写简练，用成熟库不手写轮子，优先最简单的做法，代码陈旧宁可彻底重做，不留兼容层和死代码。
- [errors](errors.md)：错误结构、全局处理、根因。立场是错误带着业务码、HTTP 状态和友好消息走统一出口，修错误修根因，不加超时或放宽断言糊过去。

## 界面

界面的视觉、交互和文案。

- [ui](ui.md)：视觉与布局。立场是简约克制、信息密度高，去装饰，主色偏稳，字重字号克制，细节用设计师的眼睛看，宽屏也要好看。
- [ux](ux.md)：交互与动效。立场是所有交互都要有克制而精致的动效，拒绝生硬跳变，交互范式参照 macOS，自由布局要加约束，次要信息默认折叠。
- [copy](copy.md)：界面文案。立场是不放解释性文案，引导可以亲切，提示和报错用规范短句，用正式全称不露技术缩写，不过度负反馈。

## 质量

测试、性能、文档。

- [testing](testing.md)：测试粒度、验收方式、审查顺序。立场是测试克制不堆覆盖率，验收在真实环境端到端看效果，测真数据不测 Mock，测试失败修产品代码不放宽断言。
- [perf](perf.md)：性能预算、延迟、构建耗时。立场是性能预算是硬上限不是目标值，延迟是一等约束，开发环境卡顿也是要查的性能问题。
- [docs](docs.md)：注释与文档。立场是注释只写 What 和 Why，半角标点，不口语不长文，文档是事实源，决策写回文档，只保留对照过源码的现行文档，行文要流畅。

## 工具链

依赖、构建、部署、git。

- [deps](deps.md)：选库标准、外部服务。立场是成熟库优先，手写轮子算坏味道，不需要的基础设施直接去掉，引入新的外部服务先经过用户。
- [tooling](tooling.md)：脚手架、CI、配置、版本。立场是工具链按官方推荐方式搭，CI 和 Dockerfile 是初始化标配，配置收敛到一份文件加环境变量，运行时跟最新 LTS，钉死版本。
- [ops](ops.md)：部署、发版、监控。立场是单机全 Docker 加反向代理加 Jenkins 自动构建，一份 .env 开箱即用，改线上配置先备份，发版自动填好信息最后人工确认，监控先抓 crash-free。
- [git](git.md)：提交粒度、提交信息、分支。立场是小步独立提交一个提交只做一件事，提交信息英文 type(scope) 加中文标题不带 AI 署名，单人项目直接在主分支上做。

## 语言

某种语言特有的品味，文件名直接用语言名。

- [dart](dart.md)：Flutter 项目的选型和习惯。立场是 Riverpod 代码生成加 go_router，弃用 GetX 和 EventBus，多平台单一代码树，FVM 钉死版本，优先热重载。
- [java](java.md)：Spring Boot 项目的习惯。立场是配置用一份 YAML 加环境变量，错误走 BizCode、BizException、全局 Handler 三件套，JDK 跟最新 LTS。
