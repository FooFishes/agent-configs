# testing

一句话立场：测试克制，不为覆盖率堆测试。验收在真实环境端到端看到效果，测真数据不测 Mock。测试失败修产品代码，不放宽断言。

## 条目

### 不写过多测试，会定期筛掉莫名其妙的测试

为什么：不是反对测试，是反对 Agent 默认大量生成。测试是要维护的代码，"不要写过多测试"说了四次，并且亲自列举筛选。

例外：暂无。

来源：eat_what_app，2026-11。

### 测试失败先判断是回归还是测试过时，修产品代码里的真实缺陷，不为了绿放宽断言

为什么：放宽断言让测试失去意义。"修根因, 不要为了通过而放宽断言"。

例外：暂无。

来源：AnkerHackathon，2026-10。

### 测真数据，去掉 Mock

为什么：Mock 测的是自己对接口的想象。"去掉 MOCK, 我们测真数据"。

例外：后端是正式环境无法造数据时，专门搭一个验收用的 Mock 环境，并且明确那是验收用的，不是运行时的。

来源：sentry-panel、eat_what_app，2026-09 至 11。

### 验收在真实环境端到端看到效果，按完整功能点验证，不按单个函数

为什么：单测通过不算完，要在浏览器里看到效果，穿过真实的反向代理，移动端上真机而不装模拟器。"一个功能点结束后再进行验证，而不要一个小 func 的去验证"。

例外：暂无。

来源：AnkerHackathon、sentry-panel、eat_what_app，2026-10 至 11。

### 接口改动后用外部脚本对契约做端到端验证，不写框架内的集成测试；OpenAPI 是交付文档不是门禁

为什么：外部脚本跑在隔离的端口和 schema 上，出一份简短报告，比框架内集成测试更接近真实调用。文档供前端使用，"不需要强制检查接口是否存在"。

例外：暂无。

来源：SentryPanelBackend、training-sys，2026-09。

### 安全相关的测试用真实的本地服务复现，正反用例都要有

为什么：SSRF 的测试方案是自己写的：本地起服务返回指向内网的 302 断言被拒，正常的公网重定向能跟到底。

例外：暂无。

来源：Nova，2026-10。

### 审查按影响面从大到小，先保证业务流程闭环没有漏洞，穷尽权限和错误边界

为什么："按照由大到小的类别进行"，"评价谁能干什么 谁不能干什么, 会产生什么报错. 尽可能穷尽一下"。

例外：暂无。

来源：training-sys，2026-09。

### 构建通过不等于类型正确，不关闭构建期的类型和 lint 检查

为什么：发现配置里开着 ignoreBuildErrors 后，选择修掉一百多个类型错误并恢复检查，而不是继续关着。

例外：暂无。

来源：training-sys，2026-09。
