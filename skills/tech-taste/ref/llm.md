# llm

一句话立场：判断类任务交给模型而不是规则，但模型选型靠自己跑基准，替换前先做评测集；确定性的事情由代码做，守卫做减法而不是整条拒绝。

## 条目

### 判断和分类逻辑优先用模型，不写规则匹配

为什么：主动盘点规则匹配点并逐个替换："现在我们有哪里是靠规则匹配去做判断的吗"，"请你查看 Jev 模型, 我们或许可以使用这个去进行分类"，"其他场景的判断都可以多用 Jev 来的. 比如风险网站的判断之类. 很多很多."

例外：暂无。

来源：2026-10-21 Nova。

### 替换核心组件前先做评测集，看延迟、准确率和置信度分布，通过了再逐个替换，保留降级

为什么："写评测脚本：整理约 100 条带标注的中英文问句，实测 ... 端到端延迟、准确率和置信度分布"，"再按清单逐个迁，每个先评测再替换"，gateway 要带"录制回放、用量、超时降级"。还专门要求"删除泄题的结果并后台重跑评测"。

例外：暂无。

来源：2026-10-21 Nova。

### 模型选型靠自己跑基准，不靠印象；延迟敏感路径关掉思考或用最低档

为什么："都有什么候选模型啊"，"跑一下视觉的benchmark看效果, 都关闭思考或者使用最低档位思考"，"只用 DeepSeek 重跑读图基准, 然后定主模型并提交"。

例外：暂无。

来源：2026-10-14、10-15 AnkerHackathon。

### 延迟是选模型的一等约束，并且按任务类型分别判断

为什么："主要是 DeepSeek 时延太高了"；"感觉都可以接, 这个延迟我们是可以接受的. 不过有些强上下文相关的生成任务确实不适合, 你看看有吗"。分类任务和强上下文生成任务的延迟容忍度不一样。

例外：暂无。

来源：2026-10-21 Nova。

为什么："作为主模型, 支持多模态 … 关闭思考作为轻量模型"，"现在的轻量模型负责什么任务"。

例外：暂无。

来源：2026-10-14、10-15 AnkerHackathon。

为什么："去掉 OCR, 使用多模态的模型去识别"。

例外：暂无。

### 只能用明确批准过的模型和外部服务

为什么："唉唉 不要随便用呀, 我只允许了那两个模型"。引入新的外部依赖要先经过用户，这既是成本也是选型意识。

例外：暂无。

来源：2026-10-14 AnkerHackathon。

### 确定性的事情由代码做，模型只消费结果；AI 推断旁边要有手动兜底入口

为什么："当用户想要修改右侧的信息时，我觉得也理应可以直接改，然后将修改后的状态交给模型，而不是像现在这样的让模型去修改"，同一句里要求"添加一下手动选择产品的途径，下拉框或者之类的"。

例外：暂无。

来源：2026-10-17 AnkerHackathon。

### 输出守卫只盯少数高风险类别，命中时删违规句保留其余，不整条拒答；不要把 Agent 管死

为什么："型号未确认时允许回答通用问题, 回答类回复允许带一个追问, 审查只查回执、承诺、无来源步骤三类, 被拦时删违规句、保留其余正文"；"我感觉现在的Agent不够灵活智能，你觉得问题在哪？"。

例外：具体盯哪几类是项目决定的，可迁移的是"做减法、按句裁剪、不整条拒绝"。

来源：2026-10-17 AnkerHackathon。

### 向用户提问以信息增益为准，系统里已有的结构化数据不再问用户

为什么："能让用户进行更少的操作，能让agent获得更有价值的信息"；"我们之前新增了用户系统和订单系统，那我们是不是就可以让Agent读取用户的订单…更加方便的确定产品型号了？"

例外：暂无。

来源：2026-10-16、10-17 AnkerHackathon。

### Agent 编排自己写，不用现成的 Agent 框架

为什么：整个项目是自写的 turn 编排器加状态机，没有 LangChain 之类；用户事后向 Agent 索要理由"ts在Agent上的优势呢?"，"如果老师问为什么不用已有的框架,而要用ts?怎么回答"。选型文档里的说法是"框架的抽象会把这些逻辑藏起来"。

例外：选择本身是事实，理由部分来自文档，标为待确认。

来源：2026-10-17 AnkerHackathon；2026-10-14 Anker 选型文档（辅助）。

### LLM 的输出按 Markdown 渲染，不把格式标记当纯文本，也不强制结构化分条

为什么："摘要中很多 Markdown 的格式标记按照纯文本的方式显示了出来"；"这个强制分条好奇怪, 同时好像还没有 Markdown 的回答格式方便阅读"。

例外：暂无。

来源：2026-10-21 Nova。
