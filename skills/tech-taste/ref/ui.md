# ui

一句话立场：简约、克制、信息密度高。去装饰，主色偏稳，字重字号克制，细节用设计师的眼睛看。界面不放解释性文案，提示和报错用规范短句。

## 条目

### 去装饰：不加图标背景块、色条、无意义的图标和发光效果，没有真实功能支撑的占位元素也不要

为什么：装饰元素不承载信息，只分散注意力。首字母头像圆圈在没有头像功能的产品里就是假功能，身份信息用姓名加角色标签就够。

例外：暂无。

来源：training-sys、Nova，2026-09 至 10。

### 主色偏深偏稳，字重克制，字号等级少，圆角适度，主按钮用实心并带一点立体感

为什么：淡色不稳，过多字号等级让层级失焦，纯扁平色块没有可点感，描边按钮不像主操作。

例外：暂无。

来源：training-sys、eat_what_app，2026-09 至 11。

### 信息密度优先，紧凑，宽屏用横向空间做双列，宽屏和桌面也要好看

为什么：卡片太大是浪费屏幕。"我的意思是你的卡片太大了"。

例外：内部后台工具可以不测响应式布局。

来源：training-sys、Nova、eat_what_app，2026-09 至 11。

### 风格简约，重视信息层级和高级感，反模板化，实用性优先于好看

为什么：默认形态"只是一个传统的 Chat Bot"，"太 Plain 太丑了"。好看但不好用的风格候选会被否。

例外：暂无。

来源：AnkerHackathon、Nova、eat_what_app，2026-10 至 11。

### 对齐看光学对齐而不是代码对齐，圆角同心一致，同类元素同一套样式，页面间间距和标题统一

为什么：用眼睛看，不是用 DOM 看。必要时画辅助线核对内外圆角的中心。顺带检查溢出和配色的可见度。

例外：暂无。

来源：training-sys、eat_what_app，2026-09 至 11。

### 布局不因文案出现、滚动或换行而跳变；Shell 固定，滚动发生在内容区，侧栏固定在视口内

为什么：跳变是最廉价也最破坏感知的缺陷。整页滚动把侧栏带走是没处理好 Shell。

例外：暂无。

来源：sentry-panel、Nova、AnkerHackathon、eat_what_app，2026-09 至 11。

### 图标用 SVG 图标库，界面字体要辨识度高且可商用

为什么：emoji 和文字图标在不同平台渲染不一致，辨识度差的字体不适合作界面字体。

例外：暂无。

来源：sentry-panel、eat_what_app，2026-10 至 11。

### 界面不放解释性、说明性文案，空状态一句话，内部工具更不解释维护者都知道的事

为什么：四个项目里反复出现。文案解释的通常是设计没说清的东西。内部技术工具"像这些我们都知道是怎么实现的"，说明放到 note 里而不是界面上。

例外：暂无。

来源：sentry-panel、webhook-relay、training-sys、isdu-app，2026-09 至 10。

### 文案尺度：引导可以亲切，提示和报错用规范短句，既不儿戏也不过于严肃；用正式全称，不露技术缩写

为什么：三次调整尺度才定下来。"这是 UI 文案, 不应当这么儿戏"，但也"不要过于严肃"。OIDC 这类缩写和简称不该出现在用户面前。

例外：暂无。

来源：training-sys、eat_what_app，2026-09 至 10。

### 负面反馈和校验提示只在真正触发时出现，不预先显示，也不宽泛地给

为什么：搜什么都带"来源不足"是"过于负反馈"。勾选协议的提示在用户点登录时才出现，能省一步就省。

例外：暂无。

来源：Nova、eat_what_app，2026-10 至 11。
