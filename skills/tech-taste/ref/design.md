# design

一句话立场：App 是产品本体，设计稿只是方向性的 Guide。原型冻结，以 App 为准，Web 原型不能 1:1 搬到移动端。

## 条目

### 设计稿是 Guide 不是法则，产品本体是 App，不能让 Design 牵引 App

为什么：这是花最多话解释理由的一条。"这里仿佛 Design 才是产品的内容, 而 App 只是一个界面. 我们要做一个 Product, 而非去做一个 Design."

例外：暂无。

来源：eat_what_app，2026-10。

### 原型冻结不更新，因为改原型的回路成本高于直接在 App 里落地

为什么：改设计稿要对话、检查、导出、覆盖一整圈，而同一圈在 App 里已经把实现落地了。各种数据校验也应当是开发时考虑的事，不是设计稿的事。

例外：暂无。

来源：eat_what_app，2026-10。

### Web 原型不能 1:1 搬到移动端，App 和 Web 的 UI/UX 规范不同

为什么：网页和 Flutter 的实现方式与设计规范都不一样，"一味 1:1 Copy Web prototype 是不是不太好呢"。

例外：Web 项目按原型严格实现，项目结构按框架最佳实践组织，两者不混。

来源：eat_what_app、sentry-panel，2026-09 至 10。

### 先确认产品形态和功能，再给四到六个设计风格候选，再开始写；原型要打磨到上线水准

为什么：形态没定就写代码，后面都是返工。候选风格要带组件，原型要用真实感的 Mock 数据，做到"和上线产品的水准一样"。

例外：暂无。

来源：isdu-app、AIC、eat_what_app，2026-09 至 10。
