# design

一句话立场：App 是产品本体，设计稿只是方向性的 Guide；原型冻结，以 App 为准；Web 原型不能 1:1 搬到移动端。

## 条目

### 设计稿是 Guide 不是法则，产品本体是 App，不能让 Design 牵引 App

为什么：这是用户花最多话解释理由的一条。"要清楚这里我们的 Design 并不是一个完全的严肃法则, 而是一个 Guide. '翻译' '检测' 这种东西是不是偏离原意了呢? 这里仿佛 Design 才是产品的内容, 而 App 只是一个界面. 我们要做一个 Product, 而非去做一个 Design."

例外：暂无。

来源：2026-10-29 eat_what_app。

### 原型冻结不更新，改原型的回路成本高于直接在 App 里落地

为什么："Prototype 只是定一个方向, 确保整体的风格是一致的. 但是具体的产品内容还是 App. 修改 Design 的 HTML 成本是很高的, 要对话 - 检查 - 导出 - 覆盖. 而这一个 Loop 在 App 中则已经把实现落地了. 所以这样会觉得是 Design 在牵引 App, 而不是 App 具有 Design. 同时各种各样的数据 Check 应当是开发时考虑到的检测内容."；"Prototype 冻结, 不更新"。

来源：2026-10-29 eat_what_app。

### Web 原型不能 1:1 搬到移动端，App 和 Web 的 UI/UX 规范不同

为什么："给出的设计稿是一个完全的网页, 而网页与 Flutter 的实现方式与设计规范也不尽相同, 所以一味 1:1 Copy Web prototype 是不是不太好呢?"；"你应当是知道的 App 和 Web 有很多 UI/UX 设计的不同"。

例外：Web 项目按原型严格实现，见 style 里"严格按视觉原型实现"。

来源：2026-10-29 eat_what_app。

### 先确认产品形态和功能，再给多个设计风格候选，再开始写

为什么："在开始写之前, 先确认产品形态与功能. 然后, 给我几个设计风格(with components)供我候选, 4-6个."；"需要详细的考虑整个产品形态"。
