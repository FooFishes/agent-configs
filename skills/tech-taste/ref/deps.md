# deps

一句话立场：成熟库优先，手写轮子算坏味道；不需要的基础设施直接去掉；引入新的外部服务先经过用户。

## 条目

### 成熟库优先，手写本可以用库解决的东西算坏味道

为什么：审查时主动把这当作一类问题："是否有地方使用了手写而非使用成熟的框架或依赖. 是否有地方写了不符合最佳实践的代码"。前端"对于组件可以使用成熟的UI库, 但是一定要符合原始的视觉风格"。重写逻辑层时"可以引入所需的依赖, 并且并不限制依赖的引入量"。

例外：决策核心和业务逻辑自己写，见 llm。

来源：2026-09-04 sentry-panel-frontend；2026-09-27 training-sys；2026-10-08 isdu-app。

## 待确认

下面几条只出现在 Agent 整理的项目选型文档里，对话里还没有直接印证，不要当作已确认的品味，等用户表态后再移到上面。

- 一类问题只用一个方案，已有一个就不再引入同类库。
- 组件尽量少，一个 Postgres 承担存储、检索和队列，不引入 Redis 或独立向量库。
- 依赖在第一个用到它的阶段加入，不提前批量装。
- 代码生成克制使用，只给机械映射的地方用，路由表手写。
- 面向国内用户的产品排除依赖 Google 服务或境外下载的包。
