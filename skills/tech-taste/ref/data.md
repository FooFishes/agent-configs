# data

一句话立场：缺失的数据按缺失处理不补造不伪装；schema 变更要先问；不信任扩展名这类表面信息。

## 条目

### 缺失数据不伪装成 0 或空，要显式说明缺失的原因

为什么：出自用户自己写的产品审阅文档，Codex 反复引用："缺失数据必须显示为未接入/不可用/范围未匹配并给出原因，不能用 0、空数组或占位数字掩盖"，缺分母时比例为 null。

例外：暂无。

来源：2026-09-10、10-10 sentry-panel（Codex 转述用户审阅文档）。

### 新增迁移和新表必须先问；全新部署的项目不考虑旧数据和脏数据

为什么："你可以理解为我们在修复后全新部署, 也就是说我们数据库基本不会有旧数据和脏数据. 对于迁移, 你可以向我询问, 除非明确的允许, 否则不考虑迁移问题."后续"同意新增这张表"，"加一个 V2 迁移吧"都是显式批准。

例外：前半句依赖"内部自用、无存量"的背景。

来源：2026-09-26 至 10-07 training-sys。

### 数据来源优先用官方和结构化来源，缺口再用官方文档补

为什么："xlsx 中关于产品信息的可以用于导入. 也可以加一下官方文档给缺失部分."

例外：暂无。

来源：2026-10-14 AnkerHackathon。

### 上传文件校验魔数或实际格式，和后缀不符要醒目提示

为什么："对于上传的文件, 我们都检测一下魔数, 或者检测一下文件格式, 如果和后缀名不同, 则给予醒目的提示"。

例外：暂无。

来源：2026-10-06 training-sys。

### 统计口径要写清楚，大屏只展示聚合数据，不展示用户 ID、请求参数和响应正文

为什么："大屏仅展示聚合数据，不展示用户 ID、请求参数和响应正文"；"DAU：当天至少成功调用一次有效业务接口的去重用户数 UV：按 user.id 去重"。

例外：暂无。

来源：2026-09-03 isdu-app。

### 时间统一用带偏移量的 ISO 8601，不接受无偏移量的时间

为什么：Agent 提出并提交了"后端统一使用带时区偏移的 ISO 8601 时间"，用户在纠正提交信息格式时保留了这个提交。

例外：方向由 Agent 提出，用户采纳，标为转述。

来源：2026-09-27 training-sys（Codex 转述）。
